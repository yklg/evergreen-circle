## 一、项目背景

### 1.1 政策与行业背景

"15 分钟生活圈"已从学术概念变成落地标准：

- **GB 50180—2018《城市居住区规划设计标准》**（住建部）把生活圈按 5/10/15 分钟分级，并给出配套设施口径；
- **TD/T 1062《城市社区生活圈规划指南》**（自然资源部）给出逐要素服务半径表（小学 500m、生鲜菜市 500m、卫生服务中心 1000m 等）；
- **商务部等 11 部门〔2021〕247 号**《关于推进城市一刻钟便民生活圈建设的意见》把"步行约 15 分钟服务半径"写成政策目标，并列出基本保障类业态清单（含药店）。

标准给了**该配什么、配多少**，但没有给**实际走不走得到**的度量手段。

### 1.2 痛点（引赛题命题原文）

赛题对痛点的描述，我们逐字认同：

> "目前的社区建设规划多依赖人工普查和静态数据，缺乏对'真实可达性'的动态考量。痛点在于：**道路并非直线，红绿灯、过街天桥、施工围挡等都会极大影响实际步行可达范围**。传统评估手段成本高、更新慢，无法精准发现'服务盲区'。"

把它拆成三个可工程化的问题：

| 问题 | 传统做法 | 症结 |
|---|---|---|
| 圈画多大 | 以中心点画 1000m 圆 | 圆不是可达域。实测四样区的 15min 可达圈圆度只有 **0.606–0.795**，最弱方向与最强方向差可达一倍以上 |
| 设施数得清吗 | 一次关键词检索 | 单一关键词漏检严重；且"直线距离内有"≠"走得到" |
| 结论可信吗 | 人工踏勘 + 静态报表 | 成本高、更新慢、口径不透明，换个人重算结果就变 |

### 1.3 我们的切入点

**把"生活圈体检"做成一次可复现的测量，而不是一份观点。**

具体是三件事：

1. **用真实路网测时代替画圆**——但**不取底层路网数据**，改用"分散点位批量测时 + 空间插值"推导连通区域（这正是赛题 30% 档明确鼓励的技术路线）；
2. **把口径写进产物**——每个数字都要能回答"按什么尺量的、哪一代口径算的、能不能复算"；
3. **把测不到什么也量化上屏**——数据缺失标成 `unknown` 而不是 `false`，降级标成"离线估算"而不是悄悄给个看起来正常的分数。

### 1.4 文献与研究基础

本项目建立在 **3 份国家标准/政策文件**与 **24 篇中外文献**（22 篇期刊与学位论文 + 2 条在线文献）的主题基础上（原文 PDF 存于本地 `参考文献/` 目录、因体积未随仓库分发，著录清单见 README §参考文献），涵盖生活圈理论与标准解读、15 分钟可达性评估方法（UNA 工具包、μCFLP 双约束模型）、供需匹配与均等化、适老化专项评估四个方向。其中 **GB 50180—2018、TD/T 1062、商务部〔2021〕247 号**三份标准被后端 `caliber.py` / `category_rule.py` 以具名方式直接引用为算法口径来源。

前后端分离，**后端只有一份代码真相**（早期的 Vercel Serverless 镜像 `api/` 已删除，避免双份真相漂移）。

│ store/ (zustand)     dataMode · taskRegistry · annotation
│ hooks/useTaskStream  SSE 订阅 + 断线重连回放缓冲
└──────────────────────────────────────────────────────────────────
     下行 REST 44 个端点          上行 EventSource 2 个 SSE 端点（共 46 个）
┌──────────────────────────────────────────────────────────────────
│ 后端 · FastAPI 0.115 + SQLite（WAL 模式）
│
│ ├ 生活圈域  app/living_circle/（27 个模块）
│ │   isochrone 等时圈引擎 · contour 等值线 · field/grid 耗时场与判定格
│ │   poi/poi_collector 设施采集去重 · blindspot 盲区 · scoring 五维评分

│ │

│ │   engine 编排 · collect · analyze · writer · spots · assemble

### 3.2 一次体检的数据流

```
用户选点 / 选区划
   ↓
intake      定格中心点、出行方式、采样档、研究半径
   ↓
plan        LLM 从 48 位名册按需组队（返回 成员+指派理由+degraded 标记）
   ↓
measure     渔网采样 → 批量距离矩阵测时 → IDW 耗时场 → 四级等值线
   ↓          └─ 反标定常态绕行系数 → 残差耗时（受阻代理）
collect     8 类 POI 多关键词检索 → 归一化去重 → IDW 耗时回填
   ↓
diagnose    1km 网格逐格三要素判定 → 盲区连通聚合 → 五维评分 + 盲区外推扣分
   ↓
report      assemble_report 纯函数装配正文/亮点/图件/证据/署名
   ↓
audit       report_contract 落库前契约校验（B5–B18）→ 不合格不入库
   ↓
done        载荷 + caliber 代次戳一起落库，SSE 推 report_ready
```

每一步都向前端推 SSE 事件（`node_update` / `thought` / `message` / `evidence` / `chart` / `progress` / `trace` / `report_ready`），工作台以"思维流"实时呈现，且**执行与传输解耦**——代理超时或浏览器断连只影响展示层，`runner` 在 worker 进程内独立驱动，前端重连后回放缓冲续看。

### 3.3 数据模式与降级链路

外部依赖不可靠是常态（配额、限流、服务未开通），因此**降级被设计成"另一种诚实形态"而不是"失败"**：

| 模式 | 触发条件 | 数据来源 | 等时圈形态 | 屏上标注 |
|---|---|---|---|---|
| **live** | 有服务端 AK 且配额充足 | 百度 API 实时调用 | 真实路网批量测时 + IDW 推导 | `data_origin='live'` · 真实数据 |
| **cache** | 同参数 30 天内 / 中心点 500m 内有既有报告 | SQLite 复用 | 与首次实跑一致 | `served_from='cache'` + 数据时点与年龄 + "本次未消耗百度额度"横幅 |
| **offline** | 无 AK / 预算耗尽 | 直线距离 × 绕行系数 | **圆形近似** | `data_origin='offline'` · 明写"圆形近似，非真实路网形状"，不出可比评分 |
| **fixture** | 演示模式 / 无网络 | 内置快照 | 历史真实跑批留档 | `data_origin='fixture'` · 内置快照 |

三条纪律让这套降级不是摆设：

1. **前端四态徽标绝不冒充**——离线估算 / 历史实时 / 真实数据 / 演示数据，配色与文案各一态；
2. **离线件必须摘除形状键**——圆形近似在数学上恒等圆度 1.000，留着它屏上就会出现"猜的比真测的更像好圈"；
3. **复用是有条件且上屏的**——命中缓存必须挂横幅说明窗口（30 天 / 辅材 7 天 / 500m），"重新体检"是唯一的强制重算入口。

### 3.5 持久化

SQLite 13 张表：`tasks`（任务与澄清）· `reports`（调研报告全文 JSON）· `living_circle_reports`（生活圈体检报告）· `report_spot_checks`（地标体检来源三元组）· `lc_cache`（采集/算路缓存，省配额且可复现）· `evidences`（全局证据溯源库）· `traces`（决策链路）· `report_feedback`（人工修正反馈）· `expert_stats`（席位统计）· `user_sources` · `subscriptions` · `destination_discovery_cache` · `settings` / `prefs`（运行时配置与偏好）。

报告整份 JSON 一次下发（`GET /api/reports/:id`），前端零额外请求即可渲染正文、trace、metrics 与结构化对象。

## 四、核心算法设计

### 4.1 等时圈：不取底层路网的可达域推导

这是本作品的技术核心，直接对应赛题 40% 的"准确渲染真实路网计算出的等时圈"与 30% 的"鼓励在不获取底层路网数据的前提下，用空间插值或扇形采样合理推导出近似连通区域"。

```
中心点 (BD-09)
   ↓  ① 渔网采样：以研究半径 2500m 布格
   ↓     standard 档 = 格阵 66×66（格边 76.9m）
   ↓     粗扫 400m 间距 → 在 [400m, 2500m] 边界带加密至 150m
   ↓  ② 批量测时：百度距离矩阵 routematrix walking，N×1 分块
   ↓     单块起源点上限实测 100 → 1049 个采样点仅需 11 次矩阵请求
   ↓  ③ 耗时场：IDW 反距离加权插值（幂次 p=2.0，近邻 k=8）
   ↓  ④ 等值线：marching-squares 提取 5 / 10 / 15 / 20 分钟四档
   ↓  ⑤ 形态诊断：八方位扇区外接距离 → 圆度 / 最弱方向 / 未测到方向数
   ↓  ⑥ 连通域修正：含中心点的连通分量才成环（排除飞地）
GeoJSON 多边形族 + 逐点实测耗时 + 口径举证对象
```

**配额账（实测）**：一份标准档体检 = 距离矩阵 11 次 + 地点检索约 27 次 + 地理编码 ≤1 次。批量矩阵相对逐点调用的收益来自百度侧单块 100 起源点的真实上限（代码默认值 25 被 `capability_manifest.json` 的实测结论覆盖为 100）。

**形状量只诊断、不入分**：八方位形状尺（`sh-2` 代）输出圆度与最弱方向，但它**不在** `scoring.WEIGHTS` 里，屏幕上也不许出现"好/坏"字样——形状测的是各向均匀性（方差），"好不好"是水平（均值），拿方差冒充均值是**已被本项目实测证伪的推断**：同址重跑的圆度极差 0.309 > 两社区之间的差 0.110。这条判断写进了口径不变式测试。

### 4.2 多源 POI 采集与清洗

```
8 类设施 × 多关键词检索（主关键词 + 兜底关键词 + 排除词）
   ↓ 名称归一化（去括号后缀、去分店串、全半角统一）
   ↓ 坐标聚簇去重（同一 POI 被多关键词命中 → 合并为一条）
   ↓ 类别归口（category_rule 的 8 类满分线：前四类 3 处、后四类 1 处）
   ↓ IDW 耗时回填（每个设施拿到"从中心点走过去要几分钟"，而非只有直线距离）
```

百度 POI 检索有两个实测硬约束被写进代码：**单页条数硬上限 20**（请求更多会被静默降级），**检索半径上限 9000m**。这类"文档没写、实测才知道"的边界全部记录在 `backend/app/living_circle/capability_manifest.json`，并在文档 §1.5 标注探测日期与可重跑脚本。

### 4.3 服务盲区识别：两把互不换算的尺

这是本作品在方法论上最容易讲错、也因此刻意做了强约束的地方。**系统同时使用两把尺，并且拒绝在它们之间换算**：

| 尺 | 怎么量 | 产出 | 用于 |
|---|---|---|---|
| **可达尺** | 实测步行耗时 + 可达多边形（满分线 20min） | `poi.categories[].in_circle` / `min_minutes` | 设施覆盖、可达性评分 |
| **1km 直线尺** | 格心到该类设施直线距离 ≤ 1000m | `blindspots[].nearest[].distance_m`、逐格台账 | 赛题规定的三要素判盲 |

两把尺**刻意不换算**——实测 15min 圈的等面积半径只有约 705–748m，而 1km 直线尺约等于 **20min** 可达尺，不等于 15min。把它们混成一个词，历史上真实导致过一句假话：直线 950m、隔河需 35min 的药店被报成"1km 内没有"，而同一份报告的盲区数据里就躺着它的 `distance_m`。现在这类结论**只许**经由一组唯一渲染器产出，前后端两侧措辞逐字对齐并由跨端测试钉住。

**判盲输出是五态而非二值**：`reachable` / `blocked`（1km 内有但步行到不了）/ `absent` / `unknown` / `missing`。`unknown` 是一等状态——旧快照缺那一格数据时读作 `unknown`，报"1km 内没有"就是伪造负结论。逐格台账里相应地用 int8 `-1/0/1` 而不是 bool。

### 4.4 五维评分与"少采集不再 rewarded"

```
总分 = (覆盖度×0.34 + 可达性×0.2125 + 多样性×0.17 + 均衡性×0.1275 + 时段暴露度×0.15) × 100 − 盲区扣分
       └─ 拿不到路况读数的样区：退回四维**原比例** 0.40/0.25/0.20/0.15 ⇒ 总分与换代前**逐位相同**
```

| 维度 | 定义 | 满分线来源 |
|---|---|---|
| 覆盖度 34% | 各类别 `min(1, 门槛项数 / ideal_circle)` 求和 / 类别数 | GB 50180 / TD/T 1062 配套口径 |
| 可达性 21.25% | 各类别最近设施实测耗时的达标度（20min 线性衰减） | 实测步行耗时 |
| 多样性 17% | 可达区内有覆盖的类别占比 | 8 类名册 |
| 均衡性 12.75% | `1 − max(各类别与理想阈值的短板)` | 前四类 3 处 / 后四类 1 处 |
| **区域交通时段暴露度 15%** | 典型高峰窗口内，取中心点**圆域**内实时路况的四档里程占比，按"档位→倍数表"加权成指数（1.00/1.15/1.60/2.40），再线性映射到 0–100（100 = 畅通） | 百度「实时路况查询」`GET /traffic/v1/around`（实测 `status=0`、`around` 半径 500–2000m 连档可用）；倍数表 `tm-1` 是**声明值、未做双时刻标定**，与声明值/文献值**并列披露** |

两条口径纪律跟着这一维一起立：**① 它量的是环境暴露度，不是任何个体的步行能力** —— 屏上与正文都不许写成"居民高峰走不到"那类断言（与 §4.5 的措辞禁令同族）；**② 缺源不是 0 分** —— 拿不到该服务的样区（凯里老街、凯里下司，实测 `coverage=absent`）整块读数不出现、退回四维，并在双社区对比里判**不可比**，因为把"没测到"算成 0 分是伪造负结论。它是五根口径轴里**第一根进复用门的解释轴**：`ev`/`cov` 进门是"改了算法"，`tv` 进门是"真的乘进了总分"。

盲区扣分：每多一处**外推**盲区扣 4.0 分，首处不扣，封顶 12.0 分。这里有一条我们主动加上的修正——盲区按**判定覆盖率外推**（`条数 / 覆盖率`，倍数封顶 5）而不是按条数直扣。原因：覆盖率低意味着"判不出盲区"，而旧口径只按条数扣分会形成**反向激励**——采集面越小、判出的盲区越少、分越高。"判不了"是数据缺口，必须让分数为此付账，但也不能放大成无限扣分，故设 0.2 的覆盖率下限。

### 4.5 残差耗时：把"测不到的阻碍"诚实命名

红绿灯、过街天桥、施工围挡在实测数据里不可单独观测，我们不做直接建模，而是把实测耗时这个标量拆开：

```
残差 = 实测分钟 − (直线米数 × 本次反标定的常态绕行系数 ÷ 声明步速 80m/min)
```

零额外外呼（只吃已落库的采样点）。三条纪律：**只按分钟呈现，不换算成百分比**；**是代理量，不指认因果**（河道、铁路、封闭街区与单次测时噪声在这份数据里不可区分，对外一律写"残差耗时/受阻代理"）；**被剔除的采样点要计数上屏**（中心点、未测时、零耗时三类），不许静默丢。

反标定实测：凯里老街 1.620、凯里下司 1.865、北京劲松 1.529、上海五角场 1.553，而口径表声明的是 1.3、文献值约 1.14——**三个值并列披露，不挑一个当唯一真值**。

### 5.2 从读数里能得到的四类结论

**① 养老设施是跨城乡的普遍短板。** 4 个社区里 3 个（北京劲松、凯里老街、凯里下司）的可达区内**养老设施为 0 处**，直接把均衡性维度（权重 12.75%）打到 0 分；只有上海五角场有 2 处。上海与北京的差距不在"有没有菜场"，而在"有没有养老"。

**② 城区成熟 ≠ 步行圈内设施充足。** 北京劲松是典型成熟居住区，POI 圈内密度最高（150/206），但可达性只有 53.0 分——反标定绕行系数虽低（1.529，四者中最接近声明值），实测耗时却普遍偏长，说明路网密但**阻隔多**。

**③ 乡镇样区暴露的是完全不同的失效模式。** 凯里下司 POI 总量仅 24 处（五角场的 11%），15min 圈面积最小（1.221 km²）、圆度最差（0.606）、最弱方向仅 54.3m、反标定绕行系数最高（1.865）。它的失效不是"走不到"，而是"根本没有"——菜市场判盲即为此。这决定了整改建议的方向完全不同。

**④ 形状量是独立信息轴。** 凯里老街 15min 圈最弱方向正北仅 438m，而最强方向 989m（比值 0.443）——一个实测凹口。这类信息在"总面积/平均半径"里被完全平均掉，但恰恰是规划介入点。

## 六、创新点

### 创新点 1 · 不取底层路网也能得到真实可达域

赛题鼓励"在不获取底层路网数据的前提下推导近似连通区域"，我们把它做成了主链路而非备选：渔网采样 → 分散点位批量测时 → IDW 插值 → marching-squares，**全程不下载、不存储、不依赖任何路网拓扑数据**，等时圈形状与底图渲染完全解耦。附带收益是这套推导**可复算**——报告里带 `interpolation_power` / `interpolation_neighbors`，拿到载荷的人能自己插一遍。

### 创新点 2 · 把"口径"当作一等公民：五根代次轴 + 单一事实源

多数同类工具的问题不是算错，而是**算完说不清按什么算的**。本作品的做法：

- 出行速度、绕行系数、判盲半径、网格粒度、满分线等全部只住在 `caliber.py` 一处，报告载荷必须随附一份 `caliber` 举证对象；
- **五根代次轴**分别管五件不同的事：`ev-2`（证据域与判盲怎么算）、`cov-1`（覆盖度分子定义）、`rc-1`（同一份耗时场怎么被解释）、`sh-2`（这一代发不发形状尺）、**`tv-1`（区域交通时段暴露度这一维）**，外加 `nar-7`（正文装配器代次，随图件/章节/措辞换代）；
  ⚠️ `tv` 是**第一根"进复用门的解释轴"**：前三根里 `ev`/`cov` 进门是因为"改了算法"，`rc`/`sh` 只做披露；`tv` 进门是因为它**真的乘进了总分** ⇒ 旧载荷必须 miss、重跑，否则五维口径的报告里第五维是上一代读数；
- 归边规则只有一句话：**"换它之后，重跑一次的答案会不会不同？"** 会 → 进复用门（旧结果不许当本次答案）；不会 → 只做披露。这条判断由元测试强制登记，"忘了决定"和"决定错边"都必须是红的。

这套机制的实际价值在一次真实事故里体现：官渡区旧报告 0 亮点/3 图，按新装配器重装得 5 亮点/5 图——如果没有代次戳，读路径会对存量行直通，用户永远看不到新正文。

### 创新点 3 · 反过度宣称：把"测不到什么"量化上屏

这是本作品与"看起来更厉害"的同类方案的分水岭，四条都有实测背书：

| 我们**不**宣称的 | 依据 |
|---|---|
| 不做**信号配时级**的时变建模（路况只做聚合） | 实测有两半。**① 仍然成立的那半**：百度步行测时是**确定性几何函数**——同参数连跑两次、以及与 6 天前落库的同一批点对照，40/40 点逐位相同（含"当地午夜 vs 工作日上午"这组对照）⇒ **未观察到时刻效应**；因百度对未知参数静默忽略，这条只表述为"未观察到"，不等于"接口不提供时刻参数"（规矩见 §1.5）。**② 被自己推翻的那半**：由①外推出的"这套流程里没有时刻轴的可用数据源"**是错的**——同一把 AK 对「实时路况查询」有权限（实测 `status=0`），已接成第五维（`tv-1`，见 §9.2 的 1d）。⇒ 所以现在不宣称的是"**等时圈里有红绿灯配时级的时刻场**"，那依然没有数据；边界拆四条见 §9.2 的 1a／1b／1c／1d |
| 不用官方等时圈服务 | 真实调用核实：HTTP 200、421ms，但 body `status=240`「APP 服务被禁用」＝个人免费 AK 无该服务权限。记成能力边界，不静默回落 |
| 不把形状量当质量分 | 同址重跑圆度极差 0.309 > 两社区之间全部差 0.110；控制面积后与可达维偏相关翻负 −0.38。⇒ "越圆越好"已证伪，形状尺只诊断、不入 `WEIGHTS` |
| 不把残差乘进总分 | 量化过：折进总分只动 0.3–2.1 分、翻转幅度 < 换近邻数 k 的摆动（0.4–0.7 分），而代价是跨社区可比性丧失。⇒ 留在解释层，并把复议门槛写进文档 |

### 创新点 4 · 结构约束机器化：守卫会自己报错，不靠人记

架构纪律不写在文档里靠自觉，而是落成可执行判据：

- **γ 静态守卫**（`scripts/check_guard_construction.py`，走 AST 不走正则）：治理闸不得被绕过、断言不得读挂钟、流水线 import 方向不得成环。违反即 CI 红；
- **落库前契约闸 B5–B18**：几何与举证契约不合格的报告**不入库**，而不是入库后再靠前端遮。B18 还管"读数与分数同源"这一半——载荷里 `coverage=ok` 而总分那句话没提第五维，同样拒签；
- **变异判别力机器**（`scripts/mutation_check.py`）：往生产代码注入变异、断言目标用例**转红**、再按 sha256 校验还原。因为"全绿只说明当前代码让测试满意，不说明测试真的在检查东西"；
- **跨端单源守卫**：SSE 事件类型、出行模式字面量、色 token、前后端措辞——专治"两端各自声明、漂移只有一边红甚至两边都绿"。其中一条真实战果：`warn` 事件自 2026-09 起后端在发、前端类型联合里没登记，传输层按 union 穷举会**静默丢弃**，直到守卫补上才被抓到；
- **棘轮（ratchet）手法**：存量债逐文件记账，两个方向都红——超线是新增违规，低于线要求同笔把账本改小。只记总数会被"修 A 两条、B 新加两条"互相抵消糊过去。

### 创新点 5 · 生活圈体检专家团是署名层，调研专家团是计算层

48 位虚拟专家 × 2 个域（L3 决策 3 / L2 策略 9 / L1 执行 36），按体检需求自动组队。关键设计选择是：**专家只负责拆解、归口与解读，等时圈/POI/评分/盲区全部是确定性规则，没有任何一步由专家执行**。

这带来三个好处：报告可复现（同样的载荷永远装配出同样的正文）；LLM 不可用时自动退化为规则模板填充，**主流程永不阻塞**；"这章谁负责"是一张单一事实源的席位表（`seat_registry.py` 四张轴），而不是动态分工的黑箱。

配套一条可见性纪律：**组队降级必须上屏**——模型返回的队不足 5 人或调用抛错，就换 10 席保底名单并把 `degraded`（`llm_error` / `team_too_small`）发到前端常驻显示；模型编出的、不在名册里的 id 逐个丢弃，**所以它编不出人**。

### 创新点 6 · 双域同源 + 地标体检入口

同一套 Agent 骨架承载生活圈体检与目的地调研两个产品域，互不共享业务代码、只共享 `core/` 底座。**地标体检**把两域打通：在目的地攻略报告里选中任一景点，即以它为圆心发起体检（来源三元组"宿主类型/报告/景点"落进侧表，复用同一条确认流——未确认不建任务、不耗配额）。这让"这个景点周边走得到医院吗"成为一个顺手可问的问题。

### 7.2 CI/CD

- **GitHub Actions（唯一真源）** `.github/workflows/ci.yml`，4 个 job：
  `backend`（γ 静态守卫 + pytest 全量）· `frontend`（lint 诊断 / typecheck / vitest / build）· `e2e`（Playwright 排版回归）· `docker`（push main 时构建镜像）；
- **Gitee Go** `.workflow/ci.yml`：真源的**子集**（backend + frontend 两个 stage），差异在那份文件里记明。

一条从踩坑里长出来的 CI 纪律：**新防线不得排在已知长期红的步骤之后**。几何层之所以是独立 job 而非并进 `frontend`，是因为 `frontend` 的 lint 步会长期红（存量 111 条 error），step 按序终止——并进去的防线**形式上"有"、实际一行没跑**。现在 lint 是 `continue-on-error: true` 的诊断，阻断权交给 vitest 里的 lint 棘轮。

### 9.3 已知精度边界

- **中心 357m 范围内无实测点**，故 5min 圈在现有采样规格下基本为外推（这是采样档位的固有结果，不是插值 bug）；补点不增加外呼数但会改变口径，需换代次；
- 步行档的"额度不成立"结论已实测：不能假设"15 分钟＝1000m"；
- IDW 参数敏感性（凯里/劲松两份实跑快照复算，与生产函数逐位对账）：`p` 从 2 改 1 或 3、`k` 从 8 改 4/16 ⇒ 圈内格平均绝对差 0.24–0.44min、最坏单格 17.1min、12–18 个圈内格跨过 20min 满分线——**与残差信号同量级**，所以它是口径而非实现细节，报告里必须逐份声明。
