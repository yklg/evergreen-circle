根因不是出错行，是两处设计缺口：① `MiniRadar.tsx` 把 `cx/cy/r/1.18/viewBox` 当五个互不约束的
手调常量，而标签内容来自后端类别名（数据驱动）——画布是常量、内容是变量；② 这条修复 2026-09-26
已提交在 `wip/domainpack` 的 checkpoint `f7ece49`（正文自陈「仅存档，未通过门禁」），**从未进入本分支**，
而本分支的雷达测试只数标签个数、从不量越界，所以没有任何一道闸会红。

修法：从 `f7ece49` **按路径**取回 5 个文件（不做整体 cherry-pick，那条分支的后端 DomainPack 与记录页
收敛仍未过门禁），并把不变量反过来——**画布由标签包围盒的并集派生**：

- `src/lib/textMetrics.ts`：`estimateTextBox`，逐码点判宽（CJK 1.0em / 拉丁 0.6em），
  ascent 1.09em / descent 0.37em，常量来自真实 Chrome `getBBox()` 实测。
- `src/lib/radarLayout.ts`：纯函数 `layoutRadar`，输出自适应 viewBox（8 维真实标签 → `0 0 242 215`）、
  由度量派生的 `labelGap`（= ascent + strokeHalf + ringPad，替代等比 1.18r）、标准朝外锚点。
- `src/components/lifecircle/MiniRadar.tsx`：不再持有任何尺寸常量；尺寸改 `w-full` + `maxWidth=派生宽度`。
- 测试：`radarLayout.test.ts`（IT-01…06）+ `miniRadar.test.tsx`（TC-09 按真实意图翻正、TC-12…14 新增）。

一处适配：`radarLayout.ts` 头注释原写 `scores.radar[].dimension` 字面量，会被
`visitorUnrated.test.tsx` 的**按源码文本**扫消费点的棘轮误登进回归面基线（纯几何函数没有「未评」分支）。

## 一条流程教训

`f7ece49` 那种「整体 checkpoint 存档、自陈未过门禁」的提交会把**已经做对的收敛**一起困在侧分支上，
而主线没有可执行的不变量时，同一缺陷会隔几天以「新 bug」的身份再出现一次（这已是本项目第二次，
前一次是历史/报告入口收敛）。判据：一条修复若只存在于未合并分支，就等于不存在；
能落进主线的最小单位是**带测试的纯函数模块**，不是分支。
