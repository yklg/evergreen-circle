## 🔍 发现的问题

### 问题 1: 后端 health 端点路径不一致

**现象**:
- 演示脚本中检查后端就绪时使用: `curl http://127.0.0.1:8010/api/health`
- 实际后端根路径为: `http://127.0.0.1:8010/` (返回 API 信息)
- `/api/health` 返回 404 Not Found

**影响**:
- 后端就绪检查可能需要最多 30 秒超时(虽然最终会通过,因为循环重试)
- 日志中出现多条 `"GET /api/health HTTP/1.1" 404 Not Found`

**建议修复**:
将演示脚本中的健康检查端点从 `/api/health` 改为 `/`:

```bash
# scripts/run-demo.sh 第 XXX 行
if curl -s "http://127.0.0.1:${BACKEND_PORT}/" >/dev/null 2>&1; then
```

### 问题 2: Fixture 数据未预加载到后端数据库

**现象**:
- 后端数据库中无 `living_circle_reports` 表
- 直接调用 `/api/life-circle/kaili` 返回 "体检报告不存在"

**影响**:
- **无实际影响**: 这是设计选择,演示模式下前端直接从本地 JSON 文件加载数据
- 但如果评审方尝试通过 API 直接获取报告数据,会得到 404

**说明**:
这是预期的架构设计:
- 演示模式 = 前端 fixture + 后端空数据库
- 真实模式 = 前端 live + 后端有数据的数据库

如果需要预加载 fixture 到数据库,可以添加一个初始化步骤:
```bash
python3 scripts/load_fixtures_to_db.py  # 需新建此脚本
```

但当前设计已经足够满足演示需求,不建议增加复杂度。
